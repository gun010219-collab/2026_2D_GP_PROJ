# CHECKMATE 출품 개발 계획

2026-11-24 개편. 최종 범위는 **5챕터, 25스테이지, King 보스전 5회**다. 작업을 시작할 때마다 이 계획, fetch한 main, 로컬 변경, 가장 최근의 사용자 승인을 대조한다. 이번 R0·D4B에 한해 사용자가 기술 승인 판단을 위임했다. R1 착수 기준은 기술 검증 통과이며, 두 단계의 인간 Windows 실전 검수는 R7에 포함한다.

R1은 Stage1~15의 실제 아트 경로를 연결했다. 전체 회귀 1,535개와 기존 캡처 80장 해시 검사 결과로 위임 기술 승인했다. 인간 Windows GUI는 R7에 포함한다. 다음 단계 R2에서 Chapter4/5 기물·전면 접합과 25개 기본 경로를 작업한다. [통합 검수표와 실행 명령](TASK5R1_CHAPTER_ART.md)

## 표시와 사건의 확장 계약

- 챕터 프로필은 환경 4종, 허용된 기물 PNG와 `animation_profile`, 기물별 레이아웃 함수를 갖는다. 실제 편성 종류와 Player만 한 번 로드한다. Stage11의 전방 기준 가시 높이는 Pawn 66, Rook 78, Knight 80px이고 HP 간격은 각각 8/10/10px이다. 기존 `sprite_layout`의 알파 발과 원근 축소, RenderMotion의 지상 좌표·18px 도약, HP 최종 패스를 사용한다. 신규 챕터는 데이터로 연결한다. 승인 후보를 다른 챕터의 대체 스프라이트로 자동 채택하지 않는다. [프로필](../arena_art_profile.py) · [대표 적용](../stage11_art_renderer.py)
- 최종 제품은 B+12, Mode1, 1440×900, 10×10, 60Hz 전투·180FPS 렌더 목표다. R1/R2에서 승인된 경로를 순차 등록하고 R2 종료 시 환경변수 없는 일반 실행을 검증한다. 기존 독립 디버그 스위치와 오류 폴백을 회귀에 남긴다. 세션 교체·실패 시 텍스처를 회수하고, 같은 실패 세션에서는 프레임마다 로딩하지 않는다.
- 표현을 사용하는 호스트는 전투 입력 전에 `flow.enable_presentation()`을 한 번 호출한다. 기존 main에서는 비활성이다. 입력과 그 프레임의 catch-up 틱이 끝나면 `events.drain()` 한 번의 불변 튜플을 Animation/VFX/Audio에 함께 전달한다. 매체별 큐를 따로 비우면 뒤 소비자가 사건을 놓친다. 다른 세션으로 넘어간 뒤에도 전달 대기 중인 이전 세션의 사건은 키로 식별한다. [사건 계약](../presentation_events.py)

| 표시 사건 | 권위 있는 발행 지점 | 소비 기준 |
| --- | --- | --- |
| telegraph | EnemyAttackLedger.create가 등록한 EnemyAttackEvent | 원래 target_cells·hit_tick·attack_kind 사용. 지속 경고·취소는 현재 ledger.state/telegraphs 확인 |
| attack_start | 유효한 플레이어 AttackEvent 최초 처리 또는 실제 due 적 공격이 prepare_attack을 통과한 시점 | 헛스윙도 궤적 가능. 공격음·광선 발사가 피해를 보장하지 않는다 |
| hit / hurt / death | CombatResolver._apply의 실제 DamageResult, Health의 실제 감소량과 hp_after | 공격자 적중·피해자 반동은 동일 영수증. HP가 0이 된 피해만 사망. Pulse 반사도 실제 공격자·피해자를 사용 |
| parry_normal / parry_perfect / parry_failed | _record_parry_result의 최초 ParryResult | 시도별 원키·reason 보존. unbound와 failed, 실제 회피·취소 사유 식별. stun은 실제 stun 성공 직후 |
| stage_transition | StageProgression._install 성공 후 새 세션 | 이전·다음 번호와 새 세션 키 사용. 같은 스테이지 재시작도 새 사건. 후보 생성 실패는 전환 없음 |

게임은 입력 시 플레이어 공격을 즉시 처리한다. `StageGame.resolve_current_tick()`은 AI/적 due 결과를 받고 종료 상태를 고정한다. 미연결 패링은 입력 때 확정될 수 있고 Pulse 반사 피해는 반환 튜플 밖의 `_apply`에서 발생한다. 따라서 마지막 결과나 렌더 프레임의 HP 차이로 사건을 재구성하지 않는다. 사건 키는 (전투·스테이지·원장 사건 또는 패링 시도 키, 표현 종류, 대상 기물)이다. 기존 단일 소비 판정에서 발행하고 프레임 사이에는 큐를 비워 중복 재생을 막는다. R3의 이동·착지 등은 같은 세션에서 실제 위치/상태 전이를 표본으로 삼는다. [전투 결과](../combat_resolution.py) · [공격 원장](../enemy_attack.py) · [스테이지 교체](../stage_progression.py)

## 검수와 인계

1. 기존 정적 회귀는 Stage5~12 캡처 66장을 임시 폴더에만 재생성해 동결 SHA-256과 대조한다. 애니메이션·VFX 추가 후에도 기존 정적 모드를 남긴다. 새 모드는 틱·사건 키·렌더 시간·파티클 시드를 고정한 별도 경로와 manifest를 사용하고 사용자 승인 후 기준을 등록한다.
2. 스테이지별로 편성, 100칸 경고와 레이어, 투영·발·깊이·HP, 에셋 누락과 세션 교체, 게임 상태 불변성을 확인한다. 기존 테스트를 삭제·완화하거나 skip을 추가하지 않는다.
3. 숨김 SDL과 direct3d11은 기술 검사다. 실제 Windows에서 창/전체화면, 조작·가독성·오디오, 장시간 성능과 인간 캠페인을 별도 기록한다. 180FPS 목표의 프레임 예산은 약 5.56ms. 실기 기록에 CPU/GPU, 주사율, VSync, 해상도, 워밍업과 측정 구간을 포함한다. [실측 절차](QA_CAMPAIGN.md)
4. R7에서 R0와 D4B를 수동 검수할 때는 저장소 루트 PowerShell에서 다음 순서로 실행한다. Stage11에서 보간·발/HP·그림자, 동시 경고와 패링, F11/ESC, GAME_OVER/R, 강화 후 Stage12 진입을 확인한다. 기본 표시와 비교하고 Stage13은 기존 D4B 18항목에 별도 기록한다.

```powershell
$env:CHECKMATE_STAGE11_ART = "1"
.\.venv\Scripts\python.exe tools\stage11_play.py
$env:CHECKMATE_STAGE11_ART = "0"
.\.venv\Scripts\python.exe tools\stage11_play.py
$env:CHECKMATE_STAGE13_ART = "1"
.\.venv\Scripts\python.exe tools\stage13_play.py
```

이번 위임은 R0와 D4B 두 커밋의 최종화에 적용한다. 신규 단계의 런타임 변경은 해당 단계의 승인 절차를 따른다. 다음 작업 단위는 R1이다.
