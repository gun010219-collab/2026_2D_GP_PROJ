## Task 1-Y-B — Pawn 인접 접촉 공격 승인

기존 대각선 공격을 우선한다. 대각선이 아니며 실제 Player가 상하좌우 인접1칸이면
이동 대신 `pawn_contact`를 기존 EnemyAttackLedger에 발행한다. 대상은 발행 시 Player 셀1칸으로 고정하고,
예고39틱·피해1·회복54틱을 기존 Pawn 정수 틱 경로로 처리한다. 이동 간격132틱은 변경하지 않는다.
Pawn은 Player 셀로 들어가지 않으며 경고 중 추적·밀어내기·즉시 충돌 피해는 없다.
일반 패링은 피해 차단, perfect는 피해 차단·Pawn 기절60틱·다음 공격+2를 적용한다.
Pulse 전용 반사2는 적용하지 않는다. 기존48틱 무적·패링 윈도우·쿨타임·보너스 비중첩/단일/미스 소모를 유지한다.
접촉은 실제 Pawn AI 계획과 원장 스냅샷·세션이 일치해야 한다. 미등록/변조/외부 세션·다른 기물의 접촉은 거절한다.
같은 공격은1회 판정하며 회피/MISS·취소·무적에서는 보상이 없다. Pawn 사망·기절·Stage 종료 시 미처리 공격을 취소한다.
기존 `_attack_moves` 계획 저장소에 정지형 접촉을 등록해 소유권과 Pulse drain을 검증하며 별도 원장/시계는 만들지 않는다.
Resolver·KingPulse·렌더러·성장/HP 프로필·다른 적 AI·Stage1~10 진행은 그대로 재사용한다.
기존 'Pawn 인접 Player를 공격하지 않고 우회' 정책은 이 승인으로 대체한다.
아래 Y-A의 '접촉 미구현'은 당시 이력이다. 사용자 Windows GUI25/25(실패0·확인 불가0·미검수0, 추가 의견 없음)를 수령했다.

## Task 1-K — Stage 1→2 진행과 챕터 재도전 (2026-11-11)

### 상태별 목적지

- PLAYING에서는 N/R 무효다. Stage 1 STAGE_CLEAR에서 N→Stage 2, R→Stage 1이다.
- Stage 2 STAGE_CLEAR는 N 무효, R→Stage 2다. 세 적이 모두 HP0이어야 클리어하며 Stage 3 진입은 없다.
- 양 스테이지 GAME_OVER는 N 무효, R→Stage 1이다. 원본의 챕터 첫 전투 재도전을 현재 Chapter 1에 적용한다.
- 동시 클리어/HP0이면 GAME_OVER 우선, 전환은 한 번 고정한다. 종료 후 시간/AI/피해/새 보상을 정지한다.
- `next_stage_number`/`restart_stage_number`는 순수 상태의 목적지 정보다. 향후 강화 메뉴는 클리어 후
  확정된 강화 선택을 거쳐 새 전투 생성에 연결해야 한다. N을 최종 강화/진행 시스템으로 간주하지 않는다.

### 입력 순서와 세션 격리

- 이전 세션을 stop하고 보류 전투 입력을 blocked로 비운 다음 새 객체를 생성한다.
  모든 실행 ID·공격/패링 기록·쿨타임·보너스·기절·무적·피격/성공 표시·Rook 계획·상태를 새로 시작한다.
  과거 원장의 결과/취소 이력은 덮어쓰지 않으며 과거 이벤트는 새 원장/소유권 검사에서 거절한다.
- N/R은 틱 전투 입력 큐 밖의 즉시 키이되 각기 별도 래치로 한 누름에 한 번만 처리한다.
  비허용 상태의 누름도 래치만 갱신해 이후 클리어에 예약하지 않는다. KEYUP/물리 키 동기화는 행동을 만들지 않는다.
- 새 입력 객체를 물리 상태에 동기화하고 수락한 키는 해제까지 잠근다. 동일 프레임의 나머지 게임/전환 키는 차단한다.
  한 프레임 세션 교체는 최대 한 번이다. 새 SimulationClock 시계를 만들지 않고 누적값과 프레임 기준을 reset한다.
- 처리 순서는 기존 SDL 배치 순서다. 메뉴/포커스 변화/앞선 F11은 N/R을 차단한다. N/R이 먼저면 새 세션 뒤
  F11/SETTINGS는 계속 처리하되 화면 변경 뒤의 오래된 마우스 좌표는 기존처럼 무시한다. 창 X는 배치 전체보다 우선한다.
- 마지막 적을 SPACE로 처치한 배치의 N/R은 평가 당시 PLAYING이면 무효다. 현재 입력/전투 틱을 끝내고

  실제 플레이에서는 기존 플레이어 공격→적 AI→적 피해 순서를 보존한다.
  마지막 Pawn의 SPACE 치명타는 예약 공격을 즉시 취소하고 현재 입력/틱을 마친 후 클리어한다.
  해당 입력 배치의 뒤따르는 이동은 전환 전 현재 틱 입력이며, 전환 이후 프레임의 게임 키는 차단한다.
- 과거 경과 틱은 매 틱 종료 조건을 확인하며 즉시 멈춘다. 마지막 새 틱은 기존처럼 입력 후 판정한다.
  동일 배치의 마지막 처치와 R 입력은 R 평가 당시 PLAYING이면 재시작하지 않는다. 해제 후 새 R을 받는다.
- 종료 전환은 `CombatResolver.stop()`으로 미처리 적 이벤트를 취소하고 연결된 패링을 실패 종료한다.
  이미 resolved인 공격/성공 결과와 영수증은 덮어쓰지 않는다.
  정지된 판정기의 advance/공격/패링 호출은 피해·보상을 만들지 않으며 렌더링도 상태를 변경하지 않는다.

### R 재시작과 입력 격리

- R은 GAME_OVER/STAGE_CLEAR에서만 허용되는 즉시 키다. 전투 입력 큐에 넣지 않고 한 누름에 한 번 처리한다.
  PLAYING에서 누른 R을 나중의 사망에 예약하지 않는다. R을 계속 누르면 재시작을 반복하지 않는다.
- `_new_game()`은 원본 Stage 1을 다시 읽어 Player/두 Enemy/Combat/Parry/PawnEncounter/Resolver/StageOneGame을 새로 생성한다.
  플레이어 HP3/(5,1)/up, Pawn HP2/원래 배치·지연, 새 entity/session/stage ID, 전투0틱과 빈 기록으로 시작한다.
  모든 공격/패링 쿨타임·보너스·기절·무적·피격/결과는 새 객체의 기본값이다. 과거 데이터를 수동 복사하지 않는다.
  이전 전투는 종료된 채 남아 있고 과거 이벤트는 새 원장에서 unknown/잘못된 소유권으로 거절된다.
- 기존 창·보드/전투 렌더러·SETTINGS·전체 화면 어댑터를 재사용한다. SimulationClock는 reset하고
  재시작 프레임 말미의 perf_counter로 프레임 기준을 다시 잡아 로딩/종료 화면 시간을 따라잡지 않는다.
- 게임 키 대기열은 blocked로 정리한 뒤 비운다. 새 GameplayInput 래치를 현재 물리 키 상태에 동기화해
  누르고 있던 방향키/SPACE/Shift를 새 명령으로 바꾸지 않는다. 해제 후 새 누름부터 동작한다.
  재시작한 프레임의 나머지 게임 키도 blocked로만 처리하여 같은 폴링 배치의 오래된 입력을 버린다.
- 화면/메뉴 입력은 기존 SDL 순서다. SETTINGS가 먼저 열리거나 F11이 먼저 처리되면 그 뒤 R은 차단한다.
  R이 먼저 허용되면 새 전투를 만든 후 같은 배치의 F11/SETTINGS는 계속 처리한다.
  메뉴의 ESC는 닫기, 메뉴 밖 ESC는 기존 종료이며 X는 전체 배치에서 우선 종료다.
  포커스 상실/복귀 프레임에는 R을 차단하고 물리 키를 동기화해 복귀 중 눌린 R을 새 누름으로 보지 않는다.

### 원본과 정수 틱 경계

원본 [게임기획서](../체크메이트_게임기획서.pdf) p.7/9/10과

기획서 p.8의 취소 규칙과 p.17의 한 입력·한 공격 연결도 확인했다.
원본 PDF/README/stage_data.json은 수정하지 않는다.

- p.7: 입력/이동→플레이어 공격→적 AI→적 공격 정렬→패링/피해→사망 판정.
- p.9: Shift 입력 당시 적중까지 남은 시간으로 등급을 정하고 실제 적중 예정 시각에 확정한다.
  입력 당시와 적중 당시 모두 같은 고정 공격 범위 안이어야 하며 취소·무적이면 성공하지 않는다.
- p.10/발표용 p.5: 일반 성공은 해당 공격 피해 무효다.
  퍼펙트는 피해 무효→공격 주체 **1초 기절**→공격 쿨타임 초기화→다음 공격 **+2**다.
  다음 공격은 시도하면 명중 여부와 관계없이 소비하며 연속 성공해도 +2만 유지한다.
  한 번의 패링은 공격 하나만 방어하며 무적 상태에서는 패링 보상을 주지 않는다.

`delta_ticks = event.hit_tick - attempt.start_tick`을 공통 60Hz Combat.tick으로 계산한다.

| 남은 정수 틱 | 실제 등급 | 원문의 연속 시간 해석 |
| --- | --- | --- |
| 1~7 | perfect | 0초 초과~0.12초 이하, 7틱은 약 0.1167초 |
| 8~18 | normal | 0.12초 초과~0.30초 이하, 8틱은 약 0.1333초 |
| 0 이하 / 19 이상 | 성공 불가 | 적중과 같은 틱/이미 지난 시각/너무 이른 입력 |

0.12×60=7.2이므로 실제 퍼펙트는 7틱까지다. 기존 임시 표시의 올림 **8틱 금색 링**은
입력 후 재생되는 preview이며 실제 등급과 분리한다. delta=18의 정상 성공은
입력 후 preview가 이미 종료된 틱에도 가능하다. 링 색/활성 여부로 성공을 판정하지 않는다.
수치와 보상은 원문 초기 구현 기준선이며 별도 최종 밸런스 승인이라고 표현하지 않는다.

### 입력 당시의 단일 연결과 실제 적중 판정

- `sdl_input.handle_key`는 기존 bool 계약을 유지하고, 유효한 새 ParryAttempt만
  `on_parry` 콜백으로 전달한다. 반복 누름/양쪽 Shift 겹침/KEYUP/쿨타임/차단/물리 키 동기화는
  새 시도나 연결을 만들지 않는다. 60틱 패링 쿨타임과 기존 입력 래치를 유지한다.
- Parry는 시도에 입력 모델 세션/스테이지 인스턴스를 부여하고 발행 payload를 보관한다.
  미등록·변조·이전 단계/다른 입력 모델의 시도는 연결할 수 없다.
  불변 ParryAttempt에는 성공 상태를 넣지 않고, 별도 frozen ParryBinding/ParryResult로 구분한다.
- 입력 틱에 현재 원장의 유효한 telegraph, 살아 있는 공격자, 현재 플레이어 칸,
  미래 hit_tick 및 delta 1~18을 확인한다. 이미 연결된 공격은 다른 시도가 예약하지 않는다.
  가능한 공격이 없어도 입력 시도와 쿨타임은 소비하고 `unbound/no_eligible_attack`으로 기록한다.
  이후 같은 틱/미래 틱에 공격이 생겨도 다시 검색하거나 연결 대상을 바꾸지 않는다.
- 복수 후보는 `(hit_tick, attack_id, 전체 scoped key)` 순서다.
  원문에 세부 동률 규칙은 없어, 현재 원장 안의 안정적인 JSON 발행 순서와 동일 틱 처리 순서를
  유지하는 기술 정책으로 선택했다. 전역 숫자 ID만으로 다른 세션/단계를 인증하지 않는다.
- 입력 때는 예상 등급과 공격만 고정한다. 성공 결과는 정확한 hit_tick 전에는 만들지 않는다.
  적중 때 진짜 원장/공격자/플레이어 생존, 고정 target_cells, 취소, 기존 피격 무적,
  원래 Parry 객체/단계/발행 시도 유효성과 미완료 연결을 다시 확인한다.
  원래 모델이나 단계가 바뀌면 연결을 실패 처리하고 과거 시도로 새 보상을 주지 않는다.
- 일반·퍼펙트 모두 기존 ledger.consume의 대상별 영수증을 먼저 한 번 확보하고
  `resolved/parried_normal` 또는 `resolved/parried_perfect`로 완료한다. 이후 보상을 적용한다.
  완료 결과는 사망/기절의 cancel_source로 덮어쓰지 않으며 재전달·렌더링·동일 시도 재사용으로
  피해/보상을 반복하지 않는다. 직접 판정 호출도 Combat/Encounter 틱이 일치해야 하므로
  잘못된 시간의 호출이 성공만 먼저 소비하고 기절 적용에서 실패하지 않는다.
- 회피는 기존 miss, 무적은 invulnerable, 취소는 cancelled 상태를 유지한다.
  연결된 시도에는 별도 failed와 evaded/invulnerable/cancelled/stale_attempt 등의 이유를 기록한다.
  단순 연결 대상 없음(unbound)과 연결 후 실패(failed)를 구분한다.

### 일반·퍼펙트 효과와 보상의 범위

일반 성공은 해당 공격 피해만 무효화한다. HP 회복/기절/공격 보너스/쿨타임 초기화/새 무적은 없다.
퍼펙트는 위 피해 무효에 다음 보상을 적용한다.

1. **공격 주체만 60틱 기절**: `[성공 틱, 성공 틱+60)`에서 이동/새 공격을 금지한다.
   점유는 유지하고 미완료 공격을 취소한다. 다른 Pawn은 계속 행동한다.
   종료 틱에 fresh AI 행동을 예약하고 과거 공격이나 남은 회복 타이머를 재활성화하지 않는다.
   재기절은 종료 시각을 갱신하며 기간을 더하지 않는다. 타이머 복귀 방식은 원문에 없어 기술 정책으로 명시한다.
2. **공격 쿨타임 초기화**: `next_attack_tick = Combat.tick`만 조정한다.
   새 공격 자동 발사, 과거 공격 ID/이펙트/소비 영수증 재활성화는 하지 않는다.
3. **다음 실제 공격 +2**: pending 보너스는 +2 하나만 유지하며 중첩/임의 만료시간이 없다.
   새 AttackEvent를 발행할 때 불변 damage_bonus에 저장하고 pending을 소비한다.
   빈 칸 공격도 소비하며 렌더나 명중 시점에 소비를 미루지 않는다. 기본 1과 합쳐 명목 피해는 3이다.
   HP 감소량은 남은 HP로 제한하므로 원래 HP2 Pawn은 한 번에 비활성화된다.
   이미 발행된 공격은 나중에 퍼펙트가 성공해도 소급 강화하지 않는다.

원문은 보너스가 빗나가도 소비된다고 명시하지만 쿨타임/보드 밖/차단 입력까지의 의미는 명확하지 않다.
현재 기존 AttackEvent 발행 계약에 맞춰 **허용되어 이벤트가 생성된 공격**을 소비 기준으로 해석한다.
이벤트가 없는 거절 입력은 보너스를 유지한다. 이는 원문에 명시된 세부 규칙이라고 주장하지 않는다.
기절/보너스/초기화의 핵심 수치와 중첩 조건은 원문에서 확인되어 구현 보류한 핵심 보상은 없다.
명시 근거가 없는 보너스 3초 만료, 추가 HP 회복/방어 무적, 일반 성공 보상은 도입하지 않는다.
킹 전체판 퍼펙트의 별도 즉시 피해 등은 Stage 1 밖이므로 이번에 구현하지 않는다.

### 기존 무적·틱·표시 보존

피격 후 48틱 `[h,h+48)` 무적을 패링보다 먼저 확인한다. 무적 중 적중한 공격은
invulnerable로 완료하고 성공/보상을 만들지 않는다. 입력 시 무적이었다는 이유로 미리 성공시키지 않으며
실제 적중 틱의 무적 종료 경계를 사용한다. 패링 자체로 무적 시작/종료를 갱신하지 않는다.
같은 틱의 다른 Pawn 공격은 JSON 순서대로 독립 처리한다. 한 공격 패링 후에도
연결되지 않은 다른 공격으로 피해를 받을 수 있고, 그 실제 피해가 48틱 무적을 시작한다.

main의 초기 열린 틱/0틱 대기 입력/이전 입력의 첫 따라잡기 틱/새 입력의 마지막 틱,
메뉴·F11·포커스 동기화와 최대 8틱 정책을 유지한다. 과거 적중을 새 Shift로 취소하지 않는다.
기절·쿨타임·연결·무적·피드백은 별도 벽시계 없이 Combat.tick만 사용한다.

입력 후 링은 PARRY WINDOW, 실제 일반은 PARRY SUCCESS/청색 모서리,
퍼펙트는 PERFECT PARRY/금색 원·광선으로 구분한다. 실패/연결 없음은 중립색 텍스트만 표시한다.

### HP와 단일 소비의 경계

- 순수 `Health`는 읽기 전용 max/current/alive와 실제 피해 틱/감소량을 관리한다.
  정수 양수 피해만 허용하고 HP는 0에서 최대 HP 사이에 유지한다. 사망한 대상의 추가 피해는 0이다.
  공격 진위·중복·무적 정책은 HP 객체가 아닌 순수 `CombatResolver`가 관리한다.
- 플레이어 SPACE는 `handle_key`의 기존 bool 소비 반환값을 유지한 채, 실제 새 AttackEvent만
  `on_attack` 콜백으로 즉시 전달한다. 렌더용 active_attack을 피해 입력으로 다시 조회하지 않는다.
  공격 생성 틱의 고정 target_cell에 있는 활성 Pawn 한 기에만 적용한다.
  빈 칸/늦은 첫 전달도 완료 처리하여 나중에 들어온 Pawn에 소급 적용하지 않는다.
- 플레이어 AttackEvent에 세션/단계/공격자 인스턴스를 추가한다. Combat이 발행한 payload와
  현재 범위가 일치해야 하며, 대상별 소비 영수증과 완료 상태를 따로 보존한다.
  이전 5필드 생성 형식은 렌더링 호환용으로 남지만 미등록 이벤트는 피해를 만들 수 없다.
- 적은 기존 EnemyAttackLedger의 대상별 consume을 재사용한다. 정확한 hit_tick에서
  유효한 활성 공격자/고정 target_cells/플레이어 생존/48틱 무적을 먼저 확인한다.
  적중만 consume→실제 HP 감소하며 회피/무적/사망 대상/늦은 전달은 소비 없이 완료한다.
  잘못된 참조·수치·범위·변조 이벤트는 영수증이나 HP 변경 전에 거절한다.
- 적 이벤트는 telegraph→due→resolved 또는 cancelled로 관리한다.
  resolved의 outcome은 hit/miss/invulnerable/target_dead/expired이며 다시 소비할 수 없다.
  이미 완료된 기록은 후속 공격자 사망으로 cancelled로 덮어쓰지 않는다.
  취소 표식·기존 소비 영수증은 보존하며 스테이지 원장 폐기 시까지 유지한다.
- 실제 실행의 Combat과 PawnEncounter가 세션/단계 ID를 공유한다.
  새 단계 바인딩은 이전 플레이어 이벤트를 무효화하고, 새 Enemy 원장은 이전 단계 이벤트를 거절한다.
  숫자 attack_id만 전역 키로 쓰지 않으며 재시작 UI 자체는 구현하지 않는다.

### 공통 틱과 입력 순서

기획서 p.7은 입력/이동→플레이어 공격→적 AI→적 공격 정렬→패링/피해→사망 판정을 명시한다.
이를 따라 새 틱에서는 입력과 플레이어 공격을 먼저 처리하고 PawnEncounter의 AI와 due 피해를 처리한다.
같은 틱의 치명적인 플레이어 공격은 해당 Pawn의 적중 예정 공격을 먼저 취소한다.
HP0 Pawn의 비활성화는 플레이어 공격 직후 즉시 수행하여 같은 틱 뒤따르는 AI가 이를 볼 수 있게 한다.
입력끼리는 사용자 요구에 따라 기존 SDL 순서·첫 방향키 우선·막힌 이동의 facing 정책을 유지한다.

- 과거 경과 틱은 Combat을 한 틱씩 진행하면서 매 틱 AI→due→피해를 완료한다.
  새로 폴링한 입력은 프레임의 마지막 새 틱에 적용하고 이미 지난 적중을 소급 취소하지 않는다.
- 이미 처리한 틱에서 새로 도착한 입력은 KEYDOWN/KEYUP 모두 순서대로 대기시켜
  다음 새 틱에서 실행한다. 초기 0틱은 입력을 먼저 받을 수 있도록 열어 둔다.
  렌더만 반복하는 프레임이 같은 전투틱의 판정 순서를 바꾸지 않도록 한 작은 기술 선택이다.
- 이전 프레임부터 대기 중인 입력은 여러 틱을 따라잡더라도 **첫 새 틱**에 적용한다.
  그 뒤 과거 틱을 처리하고 이번 프레임에 새로 폴링한 입력을 마지막 새 틱에서 처리한다.
  정상 재생에서 대기는 한 전투틱 이내이며 stall 중 벽시계 지연은 별도다.
- 메뉴/포커스/F11 입력은 즉시 처리한다. 전환 시 대기 게임 키는 blocked 처리로
  래치만 갱신한 뒤 비우고 물리 키를 동기화하여 재개 후 공격/이동이 갑자기 실행되지 않게 한다.
  현재 입력 틱에 메뉴를 열거나 F11을 눌러도 이미 열린 전환 전 틱은 완료하고 이후 틱을 정지/동기화한다.
- 같은 틱의 적 공격은 기존 JSON Pawn 순서로 발행된 attack_id 순서다.
  구체적인 정렬 키는 원문에 없어 현재 두 Pawn의 결정적 기술 정책으로 기록한다.
- 별도 피해 시계는 없다. Combat.tick과 기존 SimulationClock을 사용하고 최대 8틱/초과시간 폐기 정책을 유지한다.

## Task 1-E — Stage 1 Pawn과 적 공격 예고 기반 (2026-11-11)

### 사용자 승인 변경: 상·하·좌·우 추적 이동

- 사용자 최신 승인으로 Pawn 이동을 **상·하·좌·우 중 한 칸 이동**으로 변경한다.
  커밋 전 Task 1-E에 통합한 수정이며 별도 개발 단계가 아니다. PDF p.11의 아래 전진은 초기 기획 기록으로 보존한다.
  플레이어에게 접근하는 AI를 만들기 위한 변경이며 대각선 이동/두 칸 이동은 허용하지 않는다.
- 이동 후보에서 보드 밖, 플레이어 칸, 다른 활성 Pawn 칸을 제외하고 맨해튼 거리가 작은 칸을 우선한다.
  동률은 **상 → 하 → 좌 → 우**로 고정한다. 더 가까운 후보가 막히면 다른 유효 후보를 검토한다.
- 반복 왕복 방지를 위한 작은 구현 선택: Pawn별로 같은 플레이어 위치/다른 Pawn 점유 상태에서
  방문한 칸을 기억하고 다시 선택하지 않는다(최대 100칸). 접근 후보가 없으면 거리가 증가하는
  미방문 후보도 허용한다. 예를 들어 같은 행에서 플레이어 옆에 도착해도 대각선 공격 위치로 우회할 수 있다.
  다음 이동 검토에서 플레이어 위치 또는 다른 활성 Pawn의 점유가 달라지면 방문 기억을 초기화한다.
  물리적으로 모두 막혔거나 미방문 후보가 없으면 제자리에서 132틱 뒤 재검토한다.
  완전한 경로 탐색/최단 경로 보장은 아니며, 고정된 복잡한 배치에서는 대기할 수 있다.

  공격 칸을 결정한다. 상·좌·우 이동 후에도 forward를 회전시키지 않는다. 공격 예약이 가능하면 이동보다 우선한다.

  Pawn은 hit_tick+54까지 회복한다. 다음 행동 가능 시각에는 다시 한 번 결정한다.
  이 예약 해석은 초기 구현 선택으로 기록하며 독립 공격 주기나 피해량을 새로 확정하지 않는다.
- 초기 대기 → waiting / telegraph → recovering → 다음 행동 구조다.
  이동은 즉시 논리 칸을 바꾸고 별도 이동 애니메이션은 만들지 않는다.
  `due`는 적 공격 기록의 상태이며 실제 적중·피해·패링 결과를 뜻하지 않는다.
- 같은 전투틱 안의 Pawn은 JSON 순서로 처리해 점유 충돌을 결정적으로 해결한다.
  AI는 경과한 모든 정수 틱을 순서대로 처리한다. 같은 틱 재호출/렌더 반복은 추가 행동을 만들지 않는다.
  main은 기존처럼 경과 전투틱을 먼저 갱신하고 그 틱들의 Pawn 예약을 처리한 뒤 프레임 입력을 처리한다.
  따라서 같은 프레임의 입력으로 예고 직후 회피할 수 있지만 이미 확정된 목표를 다시 추적하지 않는다.
- 점유는 PDF의 한 칸 한 기물 규칙을 적용한다. Pawn은 다른 활성 Pawn/플레이어 칸에 들어가지 않고,
  플레이어도 활성 Pawn 칸으로 이동할 수 없다. 막혀도 facing 갱신은 유지한다.
  방향키 1회 1칸·첫 키 우선·SPACE/Shift/메뉴 입력 정책과 이동 시간 수치는 바꾸지 않는다.
  이외의 밀기/교환/포획/사망 처리는 없다.
- 취소는 ledger.cancel 또는 deactivate 연결점으로 처리한다. deactivate는 AI/점유/표시를 비활성화하고
  해당 source의 잔여 이벤트를 취소하는 내부 훅이며 HP나 사망 기능 구현이 아니다.
  외부에서 예고만 취소하면 다음 틱에 회복 대기 54틱 후 행동하도록 한다(초기 기술 선택).

### 이벤트 범위와 단일 소비 계약의 최소 구현

- `enemy_attack.py`의 frozen EnemyAttackEvent는 attack_id, combat_session_id,
  stage_instance_id, source_entity_instance_id, start_tick, telegraph_start_tick, hit_tick,
  tuple-of-tuples target_cells를 가진다. 라이프사이클 state는 별도 ledger 기록으로 관리한다.
- 숫자 attack_id는 한 ledger 안에서 단조 증가한다. 복합 key는 Task 1-D 계약의
  `(combat_session_id, stage_instance_id, source_entity_instance_id, attack_id)`다.
  적의 JSON data_id와 새 생성 UUID 인스턴스 ID를 구분한다.
- 현재 main의 새 Combat과 PawnEncounter는 같은 실행에서 함께 생성되고 ledger가 그 전투/단계의
  별도 UUID 범위를 만든다. 후속 재시작은 같은 전투 세션을 전달하더라도 **새 stage_instance_id**를 써야 한다.
  순수 테스트로 숫자 ID=1 재사용 시 이전 단계 이벤트가 거절됨을 확인하며, 실제 재시작 UI는 없다.
- create는 예고를 등록하고 mark_due는 예정 틱 도달 시 한 번만 전환한다. 반환된 due 목록은
  알림일 뿐이며 생성/만료/그리기 자체로 consume하지 않는다. 현재 main은 피해 소비를 호출하지 않는다.
- consume(event, target_entity_instance_id)는 등록된 due 이벤트를 대상별 한 번만 명시적으로 기록한다.
  HP·접촉 판정·피해 적용을 하지 않는다. 미래 호출자는 대상 위치/공격 범위/패링·취소 상태를 먼저 확인해야 한다.
- 취소된 이벤트와 다른 범위/미등록/변조 payload는 발행·소비가 거절된다.
  소비 기록과 취소 표식은 ledger 수명까지 보관한다. 스테이지 종료 시 해당 ledger를 폐기하는 구조이며
  오래된 이벤트를 새 ledger로 재전달해도 거절한다. 장시간 실행 시 기록 증가량은 후속 점검 대상이다.
- 적 사망/기절 트리거는 없으므로 현재 취소 훅을 피해·AI 통합에서 연결해야 한다.
  Rook 등 다른 AI, 범용 이벤트 버스, 실제 패링 이벤트 소비/성공 보상은 만들지 않는다.

### 시간·표시·다음 전투 통합 경계

- Combat.tick을 유일한 전투 시간 기준으로 쓴다. main의 여러 틱을 PawnEncounter가 순서대로 처리하므로
  최대 8틱 프레임에서도 예약이 건너뛰어지지 않는다. 메뉴/포커스 중에는 틱 자체가 정지한다.
  F11은 이벤트를 새로 만들지 않는다. 긴 stall 시간 일부를 버리는 기존 제한은 그대로다.
- 어두운 왕실 Pawn 임시 도형과 적색·분홍 테두리/줄무늬 경고를 쓴다.
  경고는 ledger.telegraphs의 고정 target_cells만 사용하며 금색 공격·청색 방어와 구분한다.
  렌더는 보드 → 적 예고 → 플레이어 공격 → 적 → 패링 링 → 플레이어 → 설정 UI다.
- 실제 적중 판단은 미래에 이벤트 hit_tick의 플레이어 칸/범위·취소·소비 여부를 확인해야 한다.
  패링은 Shift 시작틱과 적 hit_tick 차이를 비교하고, 현재 parry.state_at의 링 색으로 성공 등급을 정하지 않는다.
  이동 후 경고 회피, 범위 이탈, 같은 적 이벤트 중복 패링, 취소/사망/재시작은 후속 전투 테스트 대상이다.

사용자가 Windows GUI 21개 항목 통과를 보고하고 최종 자동 검수 후 커밋/기존 main 일반 Push를 승인했다.
수동 검증 항목과 자동 테스트 근거는 [PROGRESS.md](PROGRESS.md)의 Task 1-E 기록에 둔다.

## Task 1-D — 패링 가능 시간 기반과 미래 이벤트 소비 계약 (2026-11-10)

### 직접 확인한 PDF와 이번 범위의 차이

### 초기 상태·수치·입력 정책

- `PARRY_WINDOW_SECONDS=0.30` → **18틱**. `PERFECT_PARRY_WINDOW_SECONDS=0.12`는
  기존 `combat._duration_ticks`와 같은 올림 정책으로 **8틱=약 0.133333초**다.
  기준 0.12초보다 약 0.013333초 길며 최종 전투 밸런스 검토 대상이다.
- 시작틱 s일 때 `[s,s+8)`은 `perfect_window`, `[s+8,s+18)`은 `normal_window`,
  그 밖은 `inactive`. 시작 포함/종료 제외는 이번 사용자 요구 기준이며,
  PDF의 연속시간 성공 경계(0초 초과/끝점 이하)를 그대로 재현한 것이 아니다.
- `PARRY_COOLDOWN_SECONDS=1.0` → **60틱**은 PDF의 초기 기준선으로 분리한다.
  허용된 시도 시작 시 소비한다. 적이 없는 이번에는 성공/실패 결과를 만들지 않는다.
  활성/쿨타임 중 요청은 예약 없이 소비하며 창을 연장하지 않는다. 다음 시도는 s+60부터 허용된다.
- `Parry`는 자체 시계를 갖지 않고 `Combat.tick`을 request/state_at에 전달받는다.
  불변 ParryAttempt의 parry_id/start_tick/perfect_end_tick/end_tick만 기록하고
  피해/보상/성공 여부는 저장하지 않는다. 같은 틱의 상태 조회는 상태를 변경하지 않는다.
  parry_id는 현재 Parry 인스턴스 내 시도 식별자이며 attack_id와 별개이고 전역 ID가 아니다.
- 왼쪽/오른쪽 Shift는 하나의 누름 상태를 공유한다. 두 키를 겹쳐 눌러도 1회만 시도하며
  모든 Shift 해제 후 새 누름과 쿨타임 종료가 있어야 다음 시도를 시작한다.
- SETTINGS 중 누름·해제는 기록하지만 시작하지 않는다. F11 뒤 KEYUP도 처리하고
  포커스 상실/복귀·화면 전환의 기존 물리 키 동기화에 Shift 2개를 추가한다.
  동기화 자체로 시도하지 않으며 매 프레임 키 상태를 임의 초기화하지 않는다.
- SPACE/Shift/방향키는 SDL 순서와 같은 Combat 틱으로 처리하며 서로 차단하지 않는다.
  공격 36틱 쿨타임·9틱 효과는 유지한다. 패링 링은 현재 플레이어 중심을 따라간다.
- SETTINGS/포커스 정지와 F11 누적 정리는 기존 SimulationClock 정책을 그대로 쓴다.
  8틱 상한으로 긴 stall의 벽시계 시간은 버려질 수 있고, 한 프레임에 8틱이 진행되면
  8틱짜리 금색 구간을 화면에서 거의 보지 못할 수도 있다. 상태 경계의 정수틱 결정성과
  실제 화면의 시간 정밀도는 구분하며 실제 장비/최종 밸런스에서 재검증한다.
- 청색·은색 빈 링은 패링 활성, 금색 짧은 표식은 퍼펙트 **가능 구간**이다.
  SUCCESS/PERFECT 텍스트·피해 무효·기절·카메라 흔들림·소리를 만들지 않는다.
  보드→공격→패링 링→플레이어→설정 UI 순서이며 최종 에셋은 아니다.

### 미래 피해·패링 소비 계약 — 설계만 기록, 이번 미구현

- 현재 AttackEvent.attack_id는 **한 Combat 인스턴스/세션 안에서만** 고유하다.
  새 Combat의 1번 공격과 이전 세션의 1번 공격을 같은 것으로 취급하지 않는다.
  렌더링은 기존 이벤트 조회일 뿐 새 ID나 판정을 생성해서는 안 된다.
- 실제 적 도입 시 이벤트 키는 예를 들어
  `(combat_session_id, stage_instance_id, source_entity_instance_id, attack_id)`로 구분한다.
  전투 세션 ID와 스테이지 실행/재시작 인스턴스 ID는 구분하고 재시작 시 새 범위를 만든다.
  엔티티는 종류/pawn 문자열이나 리스트 인덱스 대신 해당 실행 안의 고유 생성 ID를 쓴다.
- 피해 수령 기록은 `(event_key, target_entity_instance_id)`로 관리하여 동일 대상에게 한 번만
  적용한다. 다중 대상 공격에서 서로 다른 대상은 별도 기록이며 중복과 혼동하지 않는다.
- 패링 소비는 `(enemy_event_key, defender_entity_instance_id)`를 원자적으로 한 번만 확정한다.
  같은 적 이벤트를 다음 틱/렌더 프레임/다른 시도로 다시 소비해 보상을 지급하지 않는다.
  한 시도에 연결된 적 공격 1개라는 PDF 계약도 실제 적 구현 시 검사한다.
- 취소/소멸/공격 주체 사망 시 미처리 잔여 이벤트를 무효화한다. 이미 처리한 결과와
  취소 표식을 효과가 사라졌다는 이유로 조기 삭제해 오래된 이벤트가 재적용되지 않게 한다.
  단계 종료 시 해당 범위의 이벤트와 소비 기록을 함께 폐기하고 이전 범위의 참조는 거절한다.
- 미래 테스트 전략: 동일 이벤트/대상 중복 전달, 다중 대상별 1회 적용, 두 패링 시도의 경쟁,
  취소 후 재전달, 사망 후 잔여 공격, 렌더 반복, 재시작으로 ID=1 재사용 시 범위 분리,
  이전 단계 이벤트 거절을 실제 적/피해 모듈을 만들 때 테스트한다.
  현재는 ID 유일성·불변 이벤트·렌더 무변경만 자동 검사하며 위 피해 계약의 구현 완료를 주장하지 않는다.

실제 Windows GUI 검증 전 커밋/Push는 보류한다.

  주로 적 공격 기준이며, 그대로 플레이어 예고 시간으로 가져오지 않는다.

두 PDF는 이미지형이므로 원본을 수정하지 않고 임시 이미지 사본으로 확인했다.
현재 사용자 요구가 최신 기준이며, PDF 수치가 최종 전투 밸런스로 재승인된 것은 아니다.

### 초기 구현 선택

- `ATTACK_COOLDOWN_SECONDS=0.6` → 60Hz에서 **36틱**. 유효한 보드 셀에 대한
  공격은 적 유무와 관계없이 소비한다. 이번에는 적이 없으므로 실제 HIT/피해는 없다.
- `ATTACK_EFFECT_SECONDS=0.15` → **9틱**. 별도 연출 지속시간 근거를 찾지 못해
  선택한 임시 시각 값이며, 공격 재사용 간격과 독립적이다. 최종 애니메이션/밸런스 값이 아니다.
- 보드 밖 목표의 처리 근거는 명시를 찾지 못했다. 이번에는 요청을 거절하고 이벤트·
  효과·ID·쿨타임을 소비하지 않는다. 유효한 빈 칸 공격과 구분한다.
- 불변 AttackEvent는 세션 내 단조 증가 attack_id, origin_cell, facing, target_cell,
  start_tick을 고정한다. 이동/방향 변경으로 이미 발생한 목표를 재추적하지 않는다.
  이벤트는 성공 요청에서 한 번 반환한다. 렌더 반복을 새 판정으로 사용하지 않는다.
  향후 피해 소비자는 attack_id를 기준으로 중복을 제거해야 하며 실제 피해 체계는 미구현이다.
- SPACE는 방향키와 독립적인 누름/해제 latch를 가진다. 쿨타임/메뉴 중 입력은
  소비하고 예약하지 않는다. 이후 재공격에는 KEYUP과 새 KEYDOWN이 모두 필요하다.
- 같은 프레임의 방향키/SPACE는 SDL 이벤트 순서대로 즉시 처리하고 현재 전투틱을 기록한다.
  임의의 이동 쿨타임/자동 공격/공격 중 이동 금지는 추가하지 않는다.
- `SimulationClock`은 perf_counter의 실제 프레임 경과를 누적해 고정틱을 만든다.
  한 프레임 최대 **8틱**까지만 반영하고 초과 벽시계 시간은 버려 무제한 catch-up을 막는다.
  정상 프레임 구간에서는 FPS와 독립적이나 긴 stall에서는 전투 시간이 벽시계보다 느려질 수 있다.
- SETTINGS 중 전투틱·효과 수명을 정지하고, 메뉴 전환/포커스 변경/F11 뒤 누적과 기준시각을
  정리한다. 창 전환 소요 시간이 재개 직후 전투에 몰아서 적용되지 않는다.
- KEYUP은 메뉴/F11 뒤에도 처리한다. 포커스 상실 시 latch를 정리하고 복귀·화면 전환 때
  SDL_GetKeyboardState로 물리 키를 동기화한다. 동기화 자체는 이동·공격을 만들지 않는다.
  계속 누른 키는 새 공격으로 간주하지 않으며 매 프레임 임의로 초기화하지 않는다.
- 렌더 순서: 보드 → 목표 칸의 임시 참격 → 플레이어 → SETTINGS/모달.
  효과 픽셀은 target_cell 안에만 있고 블렌드 상태나 이미지 로딩을 추가하지 않는다.

## Task 1-B — 플레이어 1칸 이동의 입력 선택 (2026-11-10)

사용자 승인 범위는 Stage 1 시작점 로딩, 방향키 단일 격자 이동과 임시 표시다.
플레이어는 논리 col/row/facing만 보관하고 픽셀 중심은 `config.cell_center`로 계산한다.
StageManager·적 점유·쿨타임·전투 규칙은 추가하지 않는다.

현재 승인 설계 문서에 경계 실패 시 facing 및 동시 키 우선순위가 명시되어 있지 않아,
이번 작은 구현 선택을 다음과 같이 기록한다.

- 초기 facing은 위쪽이다. 위치는 JSON Stage 1 player_spawn에서만 읽는다.
- 경계 이동 실패 시 위치는 유지하고 facing은 입력 방향으로 갱신한다.
- 키를 누른 순간에만 한 칸 이동한다. 누르고 있는 키의 재입력은 무시하며,
  KEYUP 후 새 KEYDOWN에서 다시 이동한다. 자동 연속 이동/시간 제한은 없다.
- 두 방향 이상 겹쳐 누르면 SDL 이벤트 순서상 첫 키만 이동한다.
  나머지는 보류 없이 소비하며 모든 방향키를 뗀 뒤 새로운 방향 입력을 받는다.
  KEYUP 자체는 이동을 만들지 않는다. 빠른 독립적인 누름/해제 순서는 순서대로 처리한다.
- 메뉴 안에서도 누름/해제를 기록하지만 이동·facing은 바꾸지 않는다.
  메뉴를 닫아도 계속 누른 키는 새 이동을 만들지 않는다.
- F11 직후 같은 입력 묶음의 마우스 좌표는 폐기하지만 방향 KEYUP은 처리한다.
  나머지 방향 KEYDOWN은 상태만 기록하고 이동하지 않아 키 해제 손실과 유령 이동을 방지한다.

설치된 Pico2D 1.5.1은 SDL의 repeat KEYDOWN을 필터링하며 반환 Event에는 repeat가 없다.
키 상태 로직은 이에 추가되는 보호 장치이며 라이브러리는 수정하지 않는다.
이 입력 선택은 전투 밸런스 수치·이동 쿨타임 확정이 아니다.
임시 은색/아이보리·청색 마커와 금색 방향 화살표는 최종 캐릭터 에셋이 아니다.
Windows 사용자 GUI 검증 전 커밋/Push는 보류한다.

## Task 1-A2 — 설정 메뉴와 전체 화면 전환 (2026-11-10)

- 실제 SDL 창 플래그로 ON/OFF를 표시한다. 전환/복원 실패는 stderr 로그와
  메뉴의 DISPLAY SWITCH FAILED 표시로 알리며 가상의 성공 상태를 저장하지 않는다.
- 버튼 위치와 클릭 영역은 `settings_menu.py`에서 동일한 Rect를 공유하고

- BGM/효과음 설정, 레이아웃 개편, 전투 시스템, 설정 파일 영구 저장은 이번 범위 밖이다.
