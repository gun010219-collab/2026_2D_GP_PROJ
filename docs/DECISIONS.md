# CHECKMATE 승인 결정

## Task 1-B — 플레이어 1칸 이동의 입력 선택 (2026-11-10)

사용자 승인 범위는 Stage 1 시작점 로딩, 방향키 단일 격자 이동과 임시 표시다.
플레이어는 논리 col/row/facing만 보관하고 픽셀 중심은 `config.cell_center`로 계산한다.
StageManager·적 점유·쿨타임·전투 규칙은 추가하지 않는다.

현재 승인 설계 문서에 경계 실패 시 facing 및 동시 키 우선순위가 명시되어 있지 않아,
이번 작은 구현 선택을 다음과 같이 기록한다.

- 초기 facing은 위쪽이다. 위치는 JSON Stage 1 player_spawn에서만 읽는다.
- 경계 이동 실패 시 위치는 유지하고 facing은 입력 방향으로 갱신한다.
- 키를 누른 순간에만 한 칸 이동한다. 누르고 있는 키의 재입력은 무시하며,
  KEYUP 후 새 KEYDOWN에서 다시 이동한다. 자동 연속 이동/시간 제한은 없다.
- 두 방향 이상 겹쳐 누르면 SDL 이벤트 순서상 첫 키만 이동한다.
  나머지는 보류 없이 소비하며 모든 방향키를 뗀 뒤 새로운 방향 입력을 받는다.
  KEYUP 자체는 이동을 만들지 않는다. 빠른 독립적인 누름/해제 순서는 순서대로 처리한다.
- 메뉴 안에서도 누름/해제를 기록하지만 이동·facing은 바꾸지 않는다.
  메뉴를 닫아도 계속 누른 키는 새 이동을 만들지 않는다.
- F11 직후 같은 입력 묶음의 마우스 좌표는 폐기하지만 방향 KEYUP은 처리한다.
  나머지 방향 KEYDOWN은 상태만 기록하고 이동하지 않아 키 해제 손실과 유령 이동을 방지한다.

설치된 Pico2D 1.5.1은 SDL의 repeat KEYDOWN을 필터링하며 반환 Event에는 repeat가 없다.
키 상태 로직은 이에 추가되는 보호 장치이며 라이브러리는 수정하지 않는다.
이 입력 선택은 전투 밸런스 수치·이동 쿨타임 확정이 아니다.
임시 은색/아이보리·청색 마커와 금색 방향 화살표는 최종 캐릭터 에셋이 아니다.
Windows 사용자 GUI 검증 전 커밋/Push는 보류한다.

## Task 1-A3 — 중앙형 게임판과 최소 HUD (2026-11-10)

사용자가 중앙형 레이아웃을 최종 승인했다. 아래 규격이 현재 화면 배치 기준이며,
이전 Task 0-B/1-A/1-A2의 75px 타일·750×750 보드·우측 고정 HUD 규격을 대체한다.
아래 과거 결정과 개발 기록은 당시 근거로 보존한다.

- 창/논리 해상도: 1440×900, CHECKMATE 제목 유지.
- 보드: 10×10, 84px 타일, 840×840, 원점 (300,30).
  오른쪽/위는 계산 상수 (1140,870), 영역은 X=[300,1140), Y=[30,870).
- 중심: `(0,0)` → (342,72), `(9,9)` → (1098,828), row=0은 아래쪽.
- 465×750 우측 고정 HUD 및 관련 배경/테두리/장식 선을 제거한다.
  좌우 각 300px는 챕터 배경과 향후 소형 실제 정보 표시용으로 비워 둔다.
  미구현 HP·쿨타임·진행 상태는 표시하지 않는다.
- 검정·금색 SETTINGS는 기존 우측 상단 좌표와 클릭 Rect를 유지한다.
  설정 오버레이는 보드 다음 최상단에 그리며 모달 동작은 유지한다.
- F11/전체 화면 상태/창 크기·위치 복원/1440×900 논리 해상도/레터박스/
  SDL 마우스 단일 변환/ESC/X 종료는 변경하지 않는다.
- 논리 스테이지 배치·수치·5개 챕터 팔레트는 유지한다. 전투/이동/AI/저장은 범위 밖이다.

새 레이아웃 사용자 GUI 검증 전 커밋/Push는 보류한다.

## Task 1-A2 — 설정 메뉴와 전체 화면 전환 (2026-11-10)

사용자가 작동하는 우측 상단 SETTINGS 버튼, 검정·금색 설정 오버레이,
전체 화면 상태/토글, 닫기 및 게임 복귀 버튼과 F11 단축키를 승인했다.
메뉴가 열리면 ESC는 메뉴를 닫고, 닫힌 상태에서는 기존 종료 동작을 유지한다.
메뉴 입력은 게임플레이로 전달하지 않는 별도 상태 처리로 분리한다.

- 논리 해상도 1440×900, 10×10 보드/75px 타일/기존 HUD 위치는 유지한다.
- SDL_WINDOW_FULLSCREEN_DESKTOP으로 모니터 해상도를 강제 변경하지 않는다.
  창·렌더러를 재생성하지 않으며 창 모드의 실제 크기/위치를 저장해 복원한다.
- SDL_RenderSetLogicalSize의 letterbox 모드로 비율을 유지한다.
  SDL이 마우스 이벤트를 논리 좌표로 변환하므로 다시 배율 변환하지 않는다.
  Pico2D 입력에는 Y축 반전만 적용하고 논리 화면 밖의 여백 좌표는 무시한다.
- 실제 SDL 창 플래그로 ON/OFF를 표시한다. 전환/복원 실패는 stderr 로그와
  메뉴의 DISPLAY SWITCH FAILED 표시로 알리며 가상의 성공 상태를 저장하지 않는다.
- 버튼 위치와 클릭 영역은 `settings_menu.py`에서 동일한 Rect를 공유하고
  SETTINGS 버튼은 보드/HUD 대신 논리 창 우측 상단에 고정한다.
- BGM/효과음 설정, 레이아웃 개편, 전투 시스템, 설정 파일 영구 저장은 이번 범위 밖이다.

설치된 Pico2D 1.5.1 / SDL2 2.32.10 API를 확인했다. SDL의
[논리 해상도와 마우스 이벤트 변환](https://wiki.libsdl.org/SDL2/SDL_RenderSetLogicalSize)을
따르며 별도 SDL_RenderWindowToLogical 호출로 이중 변환하지 않는다.
Windows 실제 GUI 검증 전 커밋/Push는 보류한다.

## Task 1-A — 챕터 아트 방향 승인 (2026-11-10)

최신 사용자 요청으로 5개 테마와 테마형 기물, 화려하되 판정을 가리지 않는
전투 피드백 방향이 승인되었다. 기존 PDF는 과거 기획 자료로 보존하고
새 비주얼의 기준은 아래 문서로 명시한다.

- Chapter 1: 왕실 정통 체스, 흑백 대리석·금속·황금.
- Chapter 2: 숲, 고목·이끼·덩굴·버섯·고대 유적.
- Chapter 3: 얼음, 얼어붙은 궁전·빙판·결정·서리.
- Chapter 4: 용암, 흑요석·마그마 균열·화산·불꽃.
- Chapter 5: 고딕 다크 판타지, 검은 대리석·성당·왕좌·붉은 보석·금속.
- 6종 기물의 역할 실루엣은 유지하며 소재와 외형만 테마화한다.
- 일반 적중/패링/퍼펙트 패링/보스 특수 공격의 시각·음향 방향을 승인한다.
  경고와 실제 공격 범위는 반드시 일치해야 한다. 히트스톱 도입/시간은 추후 테스트한다.
- 5챕터/25스테이지/보스 5전, 논리 좌표, 배치 및 전투 수치는 변경하지 않는다.
  패링 기절·쿨타임·무적 규칙은 이번 비주얼 승인으로 추가하거나 변경하지 않는다.

세부 제작 기준은 [ART_DIRECTION.md](ART_DIRECTION.md), 승인 구조 요약은
[GAME_DESIGN.md](GAME_DESIGN.md), 후속 제작 범위는 [ASSET_PLAN.md](ASSET_PLAN.md)에 둔다.
보스 명칭은 아트 콘셉트 임시명이다. Chapter 1 절차적 보드부터 구현하며,
나머지 챕터는 팔레트 준비 단계다. 최종 에셋 및 전투 이펙트 완성을 의미하지 않는다.
사용자 GUI 검증 전 Task 1-A 커밋/Push는 보류한다.

## Task 0-B — 화면 규격 변경 (2026-11-10)

사용자가 기존 1024×720에서 **1440×900**으로 변경하는 것을 최종 승인했다.
현재 화면 기준은 `config.py`에서 중앙 관리한다.

| 항목 | 승인 규격 |
| --- | --- |
| 게임 창 | 1440×900, 제목 CHECKMATE |
| 논리 보드 | 10×10, col/row 0~9, row=0은 아래쪽 |
| 타일 | 75×75px |
| 게임판 | 750×750px, 왼쪽 아래 (75,75), X=75~825 / Y=75~825 |
| 우측 UI 영역 | 465×750px, 왼쪽 아래 (900,75), X=900~1365 / Y=75~825 |

격자 중심은 `x = 75 + (col + 0.5) * 75`,
`y = 75 + (row + 0.5) * 75`로 계산한다 (`config.cell_center`).
기존 60px 타일 및 (40,60) 원점 규격은 이 결정으로 대체된다.
`stage_data.json`의 논리 좌표, 적 배치, ID 및 게임 규칙은 변경하지 않는다.
기존 PDF와 Task 0-A 기록은 과거 기준선 자료로 보존한다.

Task 0-B 부트스트랩의 ESC는 프로그램 종료다. 향후 실제 게임 상태에서의
ESC 일시정지 동작은 별도 구현하며 이번 작업에서 전투/UI를 구현하지 않는다.
