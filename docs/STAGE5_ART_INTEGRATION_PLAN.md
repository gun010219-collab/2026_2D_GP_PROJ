# CHECKMATE — Task 5-B2A 실제 Stage5 아트 통합 계획

상태: 준비 완료 / **이번 B1F에서는 구현하지 않음**.
승인 디자인은 [아트 기준선](ART_BASELINE.md)을 따르며 실제 적용 승인은 별도 검증한다.

## 범위와 폴백

- Chapter1 Stage5 실제 플레이 화면에만 새 표시 경로를 제한 적용한다.
- 기존 렌더러를 남기고 명시적 선택/폴백 경로를 제공한다. 자산 누락·로딩 실패가 전투 세션이나 진행을 손상시키면 안 된다.
- 다른24스테이지의 표시·전투 규칙은 그대로 둔다. 배경/캐릭터를 전 챕터에 일괄 적용하지 않는다.
- 검수 도구의 `make_scene`·고정된 공격/적 위치·체력은 게임 표시 경로에 가져오지 않는다.
  매 프레임 실제 StageGame/Player/Encounter/Resolver의 읽기 전용 상태를 렌더링한다.

## 기술 계약

1. `ArenaCamera`의 B안+12 표시 투영을 단일 기준으로 삼는다. `(col,row)`·100타일·충돌·공격 판정은 바꾸지 않는다.
2. 상판·프레임 개구부·위험 셀 다각형·기물 받침·보간 위치·HP·마우스 역투영이 같은 투영 함수를 사용한다.
   마우스는 먼저 레터박스/전체 화면을 논리 캔버스로 환산한 뒤 역투영하며 보드 밖은 거부한다.
3. Player/Pawn/Rook/King을 발 기준 앵커로 배치한다. 방향 표현·행간 가림·기물 깊이 정렬·HP 위치를 실제 이동에서 검증한다.
4. 배경→보드 하부/전면→상판→정확한 위험 셀→깊이 정렬 기물/공격 VFX→피드백/HP→SETTINGS 순서를 검토한다.
   효과별 앞/뒤 계층을 명시하고 경고 셀을 장식으로 확장하지 않는다.
5. 패링 준비·입력 창·실제 성공/퍼펙트·쿨다운을 구별한다. Mode1 프레임 보조는 실제 결과/미해결 원장에만 연결한다.
6. KingPulse의100칸 경고/해결/정지·재개와 King 사망 정리를 실제 상태로 표시한다. 시간/피해/AI를 바꾸지 않는다.
7. 텍스처는 챕터 진입 시 한 번 로딩하고 세션 수명과 함께 해제한다. 검수 도구의69개 누적 로딩 구조를 그대로 제품화하지 않는다.
8. 투명 실루엣과 하부 패널은 명확한 마스크/공통 경계에 종속시킨다. Chapter4/5 확장 전에
   [열린 전면 접합 결함](BUGS.md)의 구조적 해결과 전용 회귀를 완료한다.

## 검증과 사용자 승인

- 기존 전체 테스트/독립 전투 결과를 보존한다. 렌더 반복이 실제 전투 상태/원장/입력 타이밍을 변경하지 않아야 한다.
- 100칸 정점·각 중심 역투영·타일 경계·원본 target_cells 일치, 실제 이동 보간·깊이·HP 가림을 검사한다.
- 일반 공격/피격/일반 및 퍼펙트 패링/왕Pulse/보스 사망·잔여 적/클리어·재도전·챕터 전환을 실제 main 경로에서 확인한다.
- Windows GUI에서 Stage5 정상 전투, SETTINGS/F11/ESC, 창/전체 화면,60초 안정성과 새/기존 렌더러 비교를 검수한다.
- `CHECKMATE_FRAME_STATS=1`로 실제 FPS/mean/P95/P99/max/active_sim_hz/samples/Renderer·VSync를 측정한다.
  7종FPS 결정성이나 software/dummy 로그를 실제 Windows180FPS 달성 근거로 삼지 않는다.
- 승인 후에만 후속 챕터 적용 범위를 확장한다. 아트 방향 승인과 실제 게임 적용/성능 승인은 다르다.
