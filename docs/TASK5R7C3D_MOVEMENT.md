# R7-C3-D 이동 속도별 시각적 성장

로컬과 GitHub에서 조회한 `316b68550c1a3123c2a47ac45f0cacf703d472dd`의 이동 설정, 입력 쿨다운과 보상 카드 코드를 대조했다. 양쪽 이동 간격은 18/15/12틱이었다. 기존 보상 카드는 강화 데이터의 15와 12를 직접 표시했다. 보고된 15→13 표시는 재현되지 않았다.

| 실제 이동 간격 | 보상 카드 | 전투 이동 연출 |
| --- | --- | --- |
| 18틱 | 100% → 120%, +20% | 기본 이동 |
| 15틱 | 120% → 150%, +25% | 청백색 잔상 1겹과 바람 1줄 |
| 12틱 | 150%, MAX | 청백색 잔상 2겹과 방향성 바람 3줄 |

카드의 상대 속도는 `기본 간격 ÷ 표시 간격 × 100`, 현재 대비 증가율은 `(현재 간격 ÷ 다음 간격 − 1) × 100`으로 계산한다. 정식·간소 카드가 같은 계산을 사용한다. [100% → 120%](../artifacts/movement_growth_r7c3d/card-0.png) · [120% → 150%](../artifacts/movement_growth_r7c3d/card-1.png) · [150% MAX](../artifacts/movement_growth_r7c3d/card-2.png)

현재 갑옷의 기존 텍스처를 같은 카메라에 투영한다. 기존 한 칸 이동 보간이 진행되는 동안 보간 경로 뒤쪽을 샘플링한다. 이동이 차단돼 위치가 유지되거나 보간이 끝나면 효과가 생성되지 않는다. 패링 및 공격에 따른 위치 정렬, 화면·메뉴 전환, 전투 세션 전환도 잔상을 종료한다. 위험 셀과 기물보다 먼저 그리며, 이동 효과를 포함해 64효과·128요소 한도를 넘을 경우 전투 효과를 우선한다. 새 이미지·텍스처를 만들거나 viewport를 이동하는 코드가 없다. [네 갑옷 × 세 속도 실화면](../artifacts/movement_growth_r7c3d/movement.png) · [픽셀 범위와 자원 집계](../artifacts/movement_growth_r7c3d/captures.json)

## 검증

- 전체 unittest 1,688개를 실행했다. 첫 실행의 1,684개 통과 후 변경된 UI의 기댓값 4개를 갱신했다. Stage 11~13의 캡처는 각 `upgrade.png`에서 MOVE SPEED 카드 안의 795픽셀만 바뀌었다. 다른 캡처와 기존 전투 검증은 그대로 대조했다. 수정 후 해당 모듈과 신규 테스트 등 81개가 통과했다.
- 커밋 후보 첫 실행은 1,686개 중 1개가 실패했다(467.605초). 임시 복제본에서 기존 stage_data.json이 CRLF로 변환되어 원본 SHA-256 검증이 실패했다. 원본 LF 바이트를 유지하는 임시 체크아웃으로 전체를 다시 실행했다.
- UI 기댓값 갱신 뒤 전체 unittest를 다시 실행했다. 로컬 작업 트리 1,688개(438.464초), R7-B의 전용 테스트 2개와 난이도 변경을 제외한 커밋 후보 1,686개(389.296초)가 모두 통과했다. 두 실행의 실패·오류·skip은 모두 0개였다.
- 정식 Windows 루프에서 세 이동 간격 모두 오른쪽 한 칸을 이동했다. 18틱의 잔상 제출은 0회였다. 15·12틱은 입력 후 전투 틱 8~13에서 잔상이 그려졌고 정지 뒤에는 제출되지 않았다. 경계, 점유, 보간, 세션 초기화 및 예산을 회귀 테스트했다. [Windows 입력 기록](../artifacts/movement_growth_r7c3d/release-smoke.json)
- R7-B를 제외한 커밋 후보에서 렌더링 캠페인을 다시 실행했다. 25스테이지·보스 5전의 상태, 클리어 틱, 현재·최대 HP가 기존 `release_campaign_rows()`와 모두 일치했다. 기존 갑옷 QA와 이동 QA의 기록에는 R7-B가 적용된 Stage 8·10·19·20·23의 클리어 틱이 포함되어 있다. 갑옷 QA 기록은 그대로 보존했고, 이동 QA의 R7-B 적용 원본은 로컬에 보존했다. [커밋 후보 캠페인 기록](../artifacts/movement_growth_r7c3d/campaign.json)
- 창·전체 화면 Stage 24·25 퍼펙트 패링 검사에서 비교한 화면 모서리 변화는 0픽셀이었다. 퍼펙트 패링과 이동 잔상을 함께 그린 장면에서도 이동 효과로 인한 변경은 플레이어 주변에 한정됐다. [패링 프레임 검사](../artifacts/movement_growth_r7c3d/frames.json)

## Stage 24·25 Direct3D11 성능

1440×900 Windows 창에서 실제 Queen 광선 또는 King Pulse 및 퍼펙트 패링이 발생한 장면을 골랐다. 해당 장면에 최대 이동 등급의 효과가 살아 있는 상태를 고정하고, 기존 180FPS 페이서를 적용해 렌더링했다. 수치는 고정된 전투 장면의 측정값이다. 전후 각각 준비 24프레임에 이어 240프레임을 기록했다. [시각·성능·메모리 원자료](../artifacts/movement_growth_r7c3d/performance.json)

| --- | ---: | ---: | ---: | ---: | ---: |
| 24 | 177.48 → 180.06 | 6.008 / 6.019 | 3.872 / 4.439 → 4.112 / 5.174 | 165.03 → 165.32 | 85.75 / 14.38 |

각 장면에서 이동 효과까지 포함해 Stage 24는 효과 5개·요소 51개, Stage 25는 4개·56개였다. 전용·공유 GPU 메모리 샘플은 각각 전후 같았다. 성능 검수에서 추적한 텍스처 84개, 캡처에서 추적한 279개를 모두 해제했다. Stage 24에서 통합 후 처리 2프레임이 5.56ms를 넘었으며 최대 처리 시간은 6.10ms였다.

## 실기 확인

저장소 루트에서 실행한다. `--play`에 18·15·12, `--hp`에 3~6을 넣으면 임시 체크포인트로 같은 정식 전투 루프를 연다. 최대 HP와 이동 강화 레벨을 함께 수용할 수 있는 챕터를 사용한다.

```powershell
.\.venv\Scripts\python.exe tools/movement_growth_qa.py --play 12 --hp 6
```

방향키를 눌러 갑옷과 잔상을 보고, 보드 가장자리나 적 앞에서 입력해 차단 시 잔상이 생기지 않는지 확인할 수 있다. 사용자 Windows 실기 검수 8/8로 최종 승인됐다.

커밋 범위에는 `main.py`의 이동 간격 전달, `docs/PROGRESS.md`의 R7-C3-D 단락, Stage 11~13 테스트의 보상 캡처 기댓값이 포함된다. 같은 파일의 R7-B 수정과 난이도 조정은 로컬에 보존했다.
