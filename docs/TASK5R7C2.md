# CHECKMATE R7-C2 성능·안정성 검증

2026-11-27. 승인된 C1 화면과 R7-B 로컬 밸런스로 측정했다. 실제 포커스가 있는 Windows 창에서 Stage24 평균은 163.65→179.43 FPS, Stage25는 165.85→180.00 FPS였다. 180FPS 프레임 예산은 5.556ms다. 두 스테이지의 전투 처리 시간 P99는 예산 안에 들었지만, 대기를 포함한 프레임 간격 P95는 약 6.01ms였다.

## 정식 전투 루프

Windows 11 빌드 26200, Ryzen 7 9800X3D, RTX 5080 16,303MiB, 드라이버 621.24, Python 3.13.7, Pico2D 1.5.1, SDL 2.32.10. 정식 Pico2D 창 생성과 `main.run_session`을 사용했다. 1440×900, Direct3D11 가속, VSync 꺼짐, 실제 시간과 SDL 이벤트 큐, 기본 표현과 믹서를 사용했다. 사운드 출력은 dummy 장치였다. 입력 포커스를 매 프레임 확인했다.

같은 스테이지 시작 상태와 Alt 입력 틱으로 전후를 비교했다. 전 버전은 C1과 동일한 두 정점 작성 함수, 기존 Pico2D 폴링, 상대 대기를 사용했다. 표의 프레임 간격은 연속 루프의 입력 폴링 시작 시각 사이의 실측값이다. 처리 시간에는 입력·시뮬레이션·그리기·present가 들어간다. 최초 자원 로딩과 5틱 미만은 전투 표본에서 제외했다. Stage24는 160틱, Stage25는 414틱까지 진행했다. 모니터의 물리적 표시 시각은 측정하지 않았다. [창 모드 원자료](../artifacts/r7_c2/loop-desktop.json) · [숨김 창 독립 측정](../artifacts/r7_c2/loop-final.json)

## 병목과 수정

- `actor_mesh.py`, `combat_vfx_renderer.py`에서 SDL 정점의 좌표·색·UV를 기존 버퍼에 일괄 기록한다. Stage24 프로파일에서 기물 메시 함수 누적 시간은 프레임당 1.712ms, VFX 삼각형 작성은 1.461ms였다. 아래 전후 교대 측정은 장면별·버전별 600프레임이다. 각 블록에서 전체 프레임버퍼 SHA-256을 확인했다. [수정 전 프로파일](../artifacts/r7_c2/before.json) · [수정 후 프로파일](../artifacts/r7_c2/vertices.json) · [교대 측정과 해시](../artifacts/r7_c2/paired.json)
- `sdl_input.py`, `main.py`에서 매 전투 프레임 SDL 이벤트를 펌프하고 큐가 비었을 때 Pico2D의 1ms 지연을 건너뛴다. 이벤트가 있으면 기존 디코더가 배치 전체를 읽는다. 실제 창의 폴링 시간 P50은 Stage24 1.518→0.131ms, Stage25 1.522→0.143ms였다.
- `frame_timing.py`, `main.py`에서 직전 대기가 늦게 깨어난 시간을 다음 프레임 마감에 반영한다. 한 프레임 이상 늦으면 기준 시각을 다시 잡는다. 기존 60Hz 고정 틱과 렌더 목표를 유지하며 대기에는 기존 sleep을 사용한다.

## 장시간 실행과 자원 해제

숨김 Direct3D11 창에서 Stage24·25·5·10·15·20을 순환했다. **1,814.196초(30분 14초), 314,580프레임, 588회 스테이지 진입**. 게임의 전투·렌더·오디오 경로를 사용하고 반복 시험 전용 시계로 3회 렌더마다 1틱을 진행했다. 입력 폴링과 정식 대기의 속도는 앞의 정식 루프 시험에서 측정했다. [전체 메모리 시계열과 자원 계수](../artifacts/r7_c2/soak.json)

5분 예열 이후 동일 스테이지를 끝낸 지점끼리 비교했다. 단위는 MiB다. RAM은 프로세스 private bytes와 working set, GPU는 WDDM의 해당 PID 전용·공유 메모리다.

| 표본 지점 | Private 처음→마지막 (범위) | Working set 처음→마지막 (범위) | 전용 GPU 범위 | 공유 GPU 범위 |
| --- | ---: | ---: | ---: | ---: |
| Stage25 | 225.48→229.31 (225.48–294.13) | 162.29→154.09 (153.73–224.38) | 79.84–79.96 | 59.99–60.65 |
| Stage20 | 282.00→293.68 (274.11–335.10) | 189.17→184.89 (184.89–244.80) | 76.71–76.82 | 52.63–52.95 |

텍스처 **11,009/11,009**, 폰트 **12/12**, 오디오 청크 **52/52**, 음악 **6/6** 생성·해제가 일치했다. 예열 후 사용 중인 텍스처는 Stage25에서 항상 251개, Stage20에서 항상 249개였다. 최종 정리 후 네 종류 모두 0개였다. 마지막 메모리 표본은 SDL 렌더러·창 파괴 직전이다. 추적한 핸들에는 누수가 없었다. Stage20 private bytes의 처음·마지막 차이 +11.68MiB의 할당 주체와 30분 이후 추세는 미확정이다.

Stage24·25의 워밍업된 대표 장면을 각각 180회 더 그리는 동안 이미지 로드, 폰트 열기, 글자 텍스처 생성은 0회였다. 실제 창에서 스테이지 첫 프레임은 여전히 133.0ms와 137.4ms가 걸렸다. 별도 호출 추적에서 첫 이미지·아틀라스 로드에 각각 약 100ms와 109ms가 걸렸다. [로드 계수와 비용](../artifacts/r7_c2/load-audit.json)

## 회귀와 재현

- 전체 unittest **1,663/1,663** 통과(412.003초). 기존 1,659개에 정점 데이터·배치 순서 2개와 폴링·마감 보정 2개를 추가했다. [전체 로그](../artifacts/r7_c2/regression.log)
- 네이티브 SDL 큐에 각 방식당 361개 이벤트를 넣었다. Ctrl·Alt 누름과 해제, 마우스 버튼·휠, 종료를 포함해 양쪽 디코딩 결과 281개의 순서와 필드가 같았다. 반복 키와 미처리 유형 80개가 기존대로 걸러졌고 다음 폴링의 잔여 이벤트는 0개였다. [입력 대조](../artifacts/r7_c2/input-burst.json)
- Windows에서 F11 8회, 1060×710 리사이즈와 실제 설정 클릭, 두 시험 창 사이의 Alt+Tab, 비활성 중 틱 정지와 이동 억제, 복귀 후 새 이동, 보스 재시작, 다음 챕터, 종료를 확인했다. [창·입력 결과](../artifacts/r7_c2/window-final.json)
- Direct3D11과 소프트웨어 각각 25스테이지·보스 5전의 클리어 상태·틱·HP, 9개 화면 SHA-256, 음악 순서, 이어하기, 자원 계수가 C1의 동일 드라이버 기록과 일치했다. [Direct3D11 캠페인](../artifacts/r7_c2/direct3d11-campaign.json) · [소프트웨어 캠페인](../artifacts/r7_c2/software-campaign.json)
- 창과 전체화면의 정식 루프에서 연속 퍼펙트 패링은 같은 121·195·303틱에 발생했다. 모드별 clear/present는 1,006/1,006회, 고정 모서리 변화는 0회였다. Stage24·25 충돌 프레임의 국소 효과 픽셀 수도 C1과 일치했다. [창·전체화면 연속 프레임](../artifacts/r7_c2/parry/frames.json)
